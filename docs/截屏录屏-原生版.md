# 控制中心截屏与录屏：原生版

code17 / 1.0.1-rc8 预发布，2026-10-18 按用户最新要求完整构建并同签装到原无线表。当前共享 Hook v12 与 APK 载荷一致，保留原应用数据；以 [v1.0.1-rc8](https://github.com/AUTOlightup/owornate/releases/tag/v1.0.1-rc8) 提供。

## 使用流程

“截屏与录屏”是与莫奈取色、负一屏小组件并列的 OWOrnate 模块。后续安装新版 APK 后，从“发现优化 → 截屏与录屏”手动安装；已安装模块会显示在首页。安装核对已有共享组件与 helper v6，备份 Hook 并更新到 v12，定向重载一次 Launcher。打开管理器、检查状态不会自动替换 Hook。此入口只更新 Hook，不修改后台白名单。

模块页统一提供启用、停用、重新接入、截屏页和录屏设置入口。停用会先正常停止正在进行的录屏，再隐藏两个按钮；模块仍计入已安装，保留文件与画质设置。模块安装/启用状态属于 `RuntimeStateStore.capture`，录制会话结果属于 `capture_runtime`，二者分别保存。

控制中心第二页末尾有两个固定按钮，不进入原厂拖动排序列表：

- 截屏：先收起控制中心，等待退出完成，再保存 PNG。成功提示在采集之后显示。
- 录屏：先收起控制中心，再打开独立设置页。开始后关闭设置页、返回原应用，再运行系统 screenrecord。录制期间同一按钮显示红色停止方块；再次点击正常停止并等待 MP4 封装。
- 长按截屏：收起控制中心，进入 OWOrnate“截屏”页，显示图片格式、保存位置和“返回后截屏”操作；长按本身不采集。
- 长按录屏：收起控制中心，进入 OWOrnate“录屏设置”页；录制中打开时仍可修改下一段的画质，不会重复启动或停止当前录屏。

设置页提供 0.6 / 1.2 / 2.4 Mbps 三档，默认 1.2 Mbps；按目标码率每分钟约 4.5 / 9 / 18 MB。原生分辨率，帧率跟随屏幕（当前表约 60Hz），实际输出随画面更新变化，不能设置固定帧率。H.264/MP4，无声，单段最长 180 秒，到时自动保存。

截图保存在 `Pictures/OWOrnate`，录屏保存在 `Movies/OWOrnate`，完成后交给媒体扫描。操作不依赖电脑持续连接。录屏过程中服务前台运行、持有最长 190 秒亮屏锁，结束或进程退出时释放。用户拉出控制中心停止的过程会进入视频末尾，本版不额外裁剪。

## 状态与进程

`capture/capture.sh` 只包装系统 screencap/screenrecord，没有自研编码器或编码 helper。通过 setsid/nohup 启动最多三分钟的有限录制子进程，避免关闭 ADB 会话影响录制。状态文件、PID、会话 token 和输出路径由 root worker 持有；停止前校验本会话的 screenrecord 命令行，正常停止使用 SIGINT。服务使用另一条等待连接接收结束结果，停止命令不被等待操作阻塞。

管理器的 `capture_runtime` 只是操作结果投影，连接失败不等于录制已结束。录屏页每次进入都核对 root 会话，未确认时禁用开始并提供失败重试；当前录制或保存期间仍可手动重新读取。`status` 保持只读；`refresh` 在操作锁内纠正异常退出的会话与图标投影，不改部署或模块启用意图。

`Settings.System codex_capture_phase` 是控制中心图标投影，`codex_capture_enabled` 是模块按钮启用状态。面板显示期间监听两者变化，收起后移除监听，没有常驻轮询。保存期间录屏按钮仍可重试停止或长按进入设置，避免残留 stopping 锁死入口。停用状态下 root wrapper 拒绝新截屏/新录制，仍允许读取和停止已有录制。

worker 的状态核对、原生命令启动与 PID 发布共用短期操作锁，停止请求有限等待该临界区；已取消的启动不能被迟到 worker 恢复。应用内普通采集操作与停止后停用模块的事务也串行，阻止两步之间插入新采集。后台等待录制结束不持有控制锁。宿主的后台 `o(boolean)` 阶段不修改按钮 View，由主线程刷新。

入口受 STATUS_BAR 系统权限保护，仅接受 `screenshot`、`record`、`screenshot-settings`、`record-settings` 四个固定动作。设置页、接入页、前台服务均不导出，不接收任意命令、路径或其他应用传入的码率。短按、长按都等待控制中心 `onViewGone` 后再分发；未确认收起时不继续执行。

原生系统命令自行限制最长时长。启动前按三分钟目标码率加 8 MiB 检查空间；保存失败保留错误与已有录制文件，不伪报成功。源码阶段的模拟测试不能证明真实 MP4、画质、亮屏锁及 Launcher UI 已验收。

- 控制中心行为 6/6：长按去对应设置、消费手势、等待面板收起、超时不执行、保留既有渲染调用、后台阶段不操作 View，以及 stopping 允许重试。
- 小组件管理 shell 模拟 97/97；生命周期 shell 模拟 85/85，覆盖共享 Hook v12 的识别、升级与后台 Launcher 的 HOME 重建，均为模拟 Android 环境。
- Hook/脚本语法、Manifest/资源 XML 和源文件与 assets 字节一致性检查。Hook v11 和 helper v6 原始字节保留；v12 为 v11 加本次捕获按钮附加段。

状态存储 17/17、信息卡快照 13/13 通过，新增 Java/资源/Manifest/DEX 已完整构建，沿用原签名且不可调试。原表已验证第二页按钮与主题、两种长按入口、PNG 截屏、设置页退出后开始录制、录制中长按不启停、正常停止和三分钟到时自动结束；停止后服务、通知和亮屏锁释放。手动片段 52.39 秒、402×476 H.264 MP4，281 帧解码通过，开头是表盘。

实机修正了 ContentObserver 包名、A.92 无 awk、后台 Launcher 重建、前台服务复用及停止收尾、Frida density 字段取值。三分钟到时片段在静止表盘下仅输出13帧，文件播放时长约130.91秒；录制墙钟180秒并不保证播放时长恰好180秒或稳定60fps。

## 后续验收

本轮已完成构建、原表模块接入与启停、两个长按入口、从表盘采集、按钮停止、180秒自动结束、媒体解码，以及服务/亮屏锁收尾；模块启停后仍为同一 Launcher PID。模拟覆盖失败、空间不足、启动与停止竞态及异常恢复。

后续保留第三方应用动线、三档画质和高运动画面的帧率比较、长期功耗、息屏/锁屏/轻智能/MCU，以及整机重启后恢复的验收。本轮没有整机重启，也未逐项重测原有隐藏/小组件的全部交互。

## 后续功能

独立编码 helper 留到后续功能版本，再提供可选 30/60fps、超过三分钟的连续录制。当前不加入占位编码接口或未启用的录制引擎。
