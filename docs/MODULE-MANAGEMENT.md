code30 已将第三方 launcher-v1 接入同一管理框架：实际 ID 不再映射到三个官方专用页面，启停、部署和错误确认共用 LauncherPlugins 适配器。官方设置页仍按原接口工作。第三方扩展使用自有 v4 环境，shared 只保留导入包；详见 [Launcher 插件](LAUNCHER-PLUGINS.md)。下方保留第 1 步历史设计。

前三步已打入 code26 并装表，code27 新增升级与更新检查。统一页头和脚本插件开关已实测；code27 的脚本升级、配置保留与失败回滚也已实机通过。自有运行环境仍有未验收范围，见发布包 VALIDATION.md。下文保留第 1 步设计与本机测试记录。

本页记录第 1 步：统一现有莫奈、负一屏小组件、截屏录屏的管理契约与页面。第 2 步已接入 [shell-v1 插件](PLUGIN-DEVELOPMENT.md)，第 3 步已接入 [Launcher 独立载荷](LAUNCHER-PLUGINS.md)，均复用此框架。shell-v1 的 status 失败时可显式尝试清理，成功停用才移除包；Launcher 插件继续经原 Manager 确认归属与操作结果。code27 的在线检查与下载见 [更新协议](UPDATES.md)；Java 管理接口不是对外稳定 SDK。

## 组成

- `ModuleManagement`：功能名称、状态快照、支持的生命周期动作、卸载影响和动作分发。动作包括安装、更新、修复、重新接入、启用、停用、卸载、刷新。
- `ModuleManagement.State`：安装状态、三态启停值、确认状态、忙碌状态、读取错误、操作错误、成功反馈、能力限制和支持动作。只投影现有观察结果，不另建持久化状态。
- `ModuleManagementUi`：统一右上角总开关、状态反馈、模块管理按钮及卸载确认。动作在点击时重新检查最新快照；开关不乐观翻转。
- `PageRegistry.addManaged`：声明一个带统一页头的管理页；MainActivity 不再对莫奈页头作特殊处理。
- `MonetPages`、`WidgetPages`、`CaptureSetupActivity`：适配既有业务与设备操作。Capture 继续使用原 Activity，复用相同渲染器，不移动截图/录屏入口或服务。

主管理页统一为页头与总开关、状态/反馈、业务设置、模块管理操作。莫奈的配色预览与更多选项、小组件设置 Activity、截屏与录屏设置 Activity 保留。莫奈安装方案、进度和结果页及小组件接入方案保留；安装确认后的实际执行也重新检查动作可用性。

## 状态与能力

| 状态/来源 | 开关与操作 |
| --- | --- |
| 已确认的自有安装 | 已知启停值显示开/关，按模块提供启停、卸载及修复或重新接入 |
| 共享莫奈、共享捕获 | 支持原有启停，不提供单独卸载；捕获可重新接入 |
| 共享小组件 | 保留已知开启显示，开关不可点击，说明不支持独立启停/卸载；可重新接入 |
| 未安装且已确认可安装 | 开关关闭且不可点击，提供安装入口 |
| 需要更新，启停未知 | 开关未知且不可点击；已确认的自有组件提供更新，更新保留启停选择 |
| 未确认或读取失败 | 开关未知，一般写操作不可用，保留刷新；上次状态与本次错误分别展示 |
| 可识别的自有莫奈启动失败 | 仍提供显式修复；原 `ModuleManager.repair` 在执行前重新确认安装与归属，不以缓存授权直接写入 |
| 首次部署未完成、冲突或未知来源 | 不提供无依据的启停和卸载，展示原因及适用的环境入口 |
| 操作/读取期间 | 管理按钮和总开关禁用，展示处理中；旧按钮回调不能越过新状态 |

“已启用”沿用现有启用意图；`installed`/加载未确认仍按原状态文案展示，不等同运行已就绪。停用与卸载的真实动作继续由原 Manager、锁和设备脚本执行。捕获停用前停止录制、保留媒体与画质配置的规则不变。

## 本步范围

新增共用接口和 UI 层，调整三模块页面、主页面路由和已失去调用者的莫奈重试显示辅助方法。未修改 RootShell、状态存储结构、Manager 设备操作、Hook、shell、assets、资源、Manifest 或构建发布脚本。

现有运行载荷仍随 APK 提供。“更新组件”仍表示部署现有随包组件，不表示已支持联网检查更新。管理器版本号仍为 code25，下一次生成新 APK 前需升版本并保留现有 code25 产物。
